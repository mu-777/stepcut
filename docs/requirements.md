## 1. 概要

### 1.1 目的

録画済みの画面録画から、PCアプリの手順書動画を作るローカルデスクトップアプリを開発する。

### 1.2 コンセプト

- 1本の画面録画を**ステップ（場面）**に切り分ける。
- 各ステップに、テロップ、読み上げ、ズーム、ポインター、蛍光ペンを後から付ける。
- 書き出しはmp4。
- 編集内容はテキストのプロジェクトファイルに保存し、**人手でもAI（Claude / Claude Code）でも編集できる**。
- 機能は最小限にとどめる。多少の手作業は許容し、機能の追加より単純さを優先する。

### 1.3 背景

既存ツールの調査（10章）では、要件をすべて満たし、かつAIから編集できるツールは見つからなかった。

## 2. 用語

| 用語 | 定義 |
|---|---|
| ソース | 取り込んだ録画ファイル（mp4）か画像（png・jpg・webp） |
| ステップ | 出力動画を構成する単位。ソースの区間（In/Out）、テロップ、読み上げ文などを持つ |
| 通常ステップ | 等速で再生するステップ |
| 早送りステップ | 指定した速度で再生するステップ |
| 保持（ホールド） | 指定時点のフレームを静止表示し続けること |
| 余白 | 録画の周りの上下左右の空き。プロジェクト共通の値をステップごとに上書きできる。0なら全画面 |
| 映像側座標 | ソース映像に対する座標。ズームに追従する |
| 画面側座標 | 出力動画に対する座標。ズームの影響を受けない |
| 読み上げエンジン | 文章から音声を生成する仕組み。本体内蔵のOS標準音声と、プラグインがある |
| 読みの辞書 | 誤読する語の読み方を登録し、エンジンに渡す前に文字列を置き換える仕組み |

## 3. スコープ

### 3.1 対象

| 分類 | 機能 |
|---|---|
| 構成 | ソース（複数可）の取り込み、ステップへの切り分け、区間の再利用、カット（捨てる）、早送りステップ、ステップの始まり・終わりのフェード |
| 尺の調整 | 任意の時点での保持、読み上げが長い場合の自動保持 |
| レイアウト | 上下左右の余白、出力サイズの変更、背景、映像のドロップシャドウ |
| 文字 | テロップ（画面上の任意の位置）、SRT出力 |
| 音声 | 読み上げ（OS標準を内蔵、プラグインで拡張）、読みの辞書、元音声のON/OFFと音量 |
| 強調 | 手動ズーム（ズーム中の静止も可）、擬似ポインター、蛍光ペン、図形（四角・矢印・文字。四角には画像を入れられる） |
| AI連携 | 公開仕様のプロジェクトファイル、CLIでの書き出し、フレーム画像の書き出し、外部変更の検知 |
| 出力 | mp4、SRT |

### 3.2 対象外

| 機能 | 理由 |
|---|---|
| 画面録画、Webカメラ | 録画は別ツールで行う前提 |
| 自動ズーム | ズーム位置はユーザーがUIで指定する |
| ブラウザで開くWebアプリ版、クラウド連携 | ローカルで完結させるため |
| フェード・フラッシュ以外のアニメーション | 機能を最小限にするため |

### 3.3 将来の候補（現時点では入れない）

| 機能 | 備考 |
|---|---|
| 円・吹き出しなど、四角・矢印以外の図形 | 四角（角丸・画像を含む）・矢印・文字で当面は足りる見込み |
| mp4・画像以外の入力形式 | 取り込み処理は後から形式を追加できる構造にする |
| Mac版 | 構造としてはMac対応を前提にする（C2） |

## 4. 制約条件

| ID | 制約 | 影響・注意点 |
|---|---|---|
| C1 | ローカルで完結する | アプリ本体は、読み上げを含めネット接続なしで全機能が動く。ユーザーが自分で有効にした外部の接続（Azure AI Speech など）だけはネットにつながり、その費用はユーザーが持つ。例外として、新しい版の確認（GitHub Releases を読むだけ。既定オン、アプリの設定で止められる。失敗しても何も起きない）は通信する（[decisions/20261113-update-check.md](decisions/20261113-update-check.md)）。プラグインが外部と通信するかはプラグイン次第（[decisions/20261111-external-tts.md](decisions/20261111-external-tts.md)） |
| C2 | Windowsから始め、Macへ移植できる構造にする | OS依存部分（読み上げ、エンコード、フォント）を差し替え可能な層に分離する |
| C3 | Apache-2.0で公開する | 依存ライブラリにGPLなど公開ライセンスと両立しないものを含めない |
| C4 | H.264/AACの特許への配慮 | OSまたはハードウェアのエンコーダーを使う方式を基本にする（OpenScreenに前例あり）。法的な確認は別途必要 |
| C5 | 人とAIの両方が編集できる | プロジェクトファイルの仕様を公開し、安定させる |
| C6 | プラグインがなくても全機能が動く | プラグインはすべて追加の選択肢という位置づけ |
| C7 | 機能は最小限にする | 3.2の対象外を維持する判断基準 |
| C8 | フォントは同梱しない | OSにあるフォントを使う。OSによって見た目が変わることは許容する |

## 5. 機能要件

### 5.1 プロジェクトとソース（PRJ）

| ID | 要件 |
|---|---|
| PRJ-01 | 1つのプロジェクトに複数のソースを登録できる |
| PRJ-02 | 入力形式はmp4と画像（png・jpg・webp）。画像は止まった映像として扱い（音なし）、ステップの長さを自由に決める（追加したときは 3 秒。クリップの両端で伸び縮みでき、設定パネルは In/Out・速度・録画の音声の代わりに長さを出す）。取り込み処理は形式を追加できる構造にする（[decisions/20261111-image-source.md](decisions/20261111-image-source.md)） |
| PRJ-03 | 解像度の異なるソースの表示位置・サイズはユーザーが調整できる |
| PRJ-04 | プロジェクトはテキスト形式（JSON）で保存する |
| PRJ-05 | 素材への参照：プロジェクトと同じフォルダかその下にあれば相対パス、それ以外は絶対パスで保存する（Shotcutと同じ方式） |
| PRJ-06 | 自動保存はクラッシュ復旧専用とし、本体のファイルとは別に保存する。再起動時に復元するか確認する（未保存の変更があるとき最後の変更の 5 秒後に、アプリの設定フォルダーの `recovery/` へプロジェクトごとに 1 ファイル残す。保存・破棄・正常終了で消え、クラッシュ・強制終了のときだけ残る） |
| PRJ-07 | Undo/Redoに対応する |
| PRJ-08 | 素材のファイルが見つからないときは、内部のエラー文ではなく「録画・画像が見つかりません」とパスを出し、その場で場所を選び直せる（素材のパスだけを差し替える）。開けなかったプロジェクトファイルは、ファイル名を添えて知らせる |

### 5.2 ステップ構成（STP）

| ID | 要件 |
|---|---|
| STP-01 | ステップはソースの区間（In/Out）を参照する |
| STP-02 | 1本のソースを複数のステップに切り分けられる。ステップごとに録画し直す必要はない |
| STP-03 | 同じ区間を複数のステップで再利用できる |
| STP-04 | どのステップにも含まれない区間は出力しない（カット） |
| STP-05 | ステップを分割できる。分割した後半は「新しいステップにする」か「捨てる」かを選べる |
| STP-06 | ステップの並び替え、複製、削除ができる |
| STP-07 | ステップは「通常」と「早送り」の2種類。早送りでは再生速度を指定する |
| STP-08 | 1ステップに読み上げを複数置ける。それぞれ開始時刻を持ち、省略すると前の読み上げの直後から読む。最初の読み上げは既定でテロップの文を読む（[decisions/20261026-step-based-model.md](decisions/20261026-step-based-model.md)） |
| STP-09 | 同じ録画の続いた区間で速度が同じなら、隣り合うステップを1つにまとめられる。前のステップの自動保持は明示した保持にして、後ろの要素の時刻を保つ。テロップは同じ文なら1つ、違えば改行でつなぐ |
| STP-10 | 録画を追加したとき・ステップを分割したときの後半は、空のテロップと、テロップの文を読む読み上げ(文を書き換えるまでテロップに合わせる)を付けたステップにする。空のテロップは編集画面のプレビューにだけ仮の文を出し、書き出しには出さない |
| STP-11 | ステップの始まりにフェードイン（黒から現れる）、終わりにフェードアウト（黒へ消える）を秒で指定できる。背景・録画・テロップと音声をまとめて掛ける。ほかの切り替え効果（ステップ間のクロスフェードなど）は持たない。保持と重ねても、保持の間は止めた映像のまま背景ごと黒から現れる。タイムラインの映像のクリップに、フェードの区間を黒の三角と斜めの線で示す |

### 5.3 時間と尺の調整（TIM）

| ID | 要件 |
|---|---|
| TIM-01 | ステップ内の要素（保持、ズーム、ポインター、蛍光ペン、テロップの表示時間）の時刻は、**ステップ内の出力時刻**で持つ |
| TIM-02 | ステップ内の任意の時点に保持を入れられる。保持する長さを指定する |
| TIM-03 | 読み上げの終わりが映像より後になる場合、ステップの最終フレームを自動で保持し、尺を合わせる。読み上げの開始位置はステップ内の出力時刻で指定できる（既定は先頭） |
| TIM-04 | 映像が読み上げより長い場合は、そのまま再生する（読み上げ後は読み上げなしで映像が続く）。必要ならユーザーがSTP-05で分割して捨てる |
| TIM-05 | 早送りステップでも、TIM-02〜TIM-04を同じように適用する |

### 5.4 レイアウト（LAY）

| ID | 要件 |
|---|---|
| LAY-01 | 録画の周りの余白を上・下・左・右ごとに指定する。すべて0なら全画面。余白・「枠に合わせて切り取る」・ドロップシャドウ（録画の枠）は全体の設定を持ち、ステップごとに上書きできる（テロップの位置と同じ継承）。ステップの詳細の「録画の枠」の欄で、上書きしているか（このステップだけ / 全体の設定）を示し、「この枠を共通にする」（全体の枠にして、そのステップの上書きを消す）と「全体の枠に戻す」を押せる。背景は全体だけ（[decisions/20261031-margin-layout.md](decisions/20261031-margin-layout.md)） |
| LAY-02 | 出力サイズを指定できる。既定は16:9 |
| LAY-03 | 録画は余白の内側に縦横比を保って収める。「枠に合わせて切り取る」を選ぶと、余白の内側いっぱいに描いて録画の端を切り取る |
| LAY-04 | 背景を設定できる。単色・グラデーション（線形、2〜4色）・画像から選ぶ。画像はプリセット（同梱）か任意のファイル。既定はプリセット画像。単色に切り替えたときの色は、録画の影が見え白いテロップが読める中くらいの暗さの青みの灰色 |
| LAY-05 | 録画にドロップシャドウを付けられる |
| LAY-06 | 既定の余白は上4%・下20%・左右は上と同じ幅（16:9で）とし、下の余白にテロップを置く |
| LAY-07 | 余白は数値（出力のピクセル）で入力できる |
| LAY-08 | プレビュー上で録画の枠を操作できる。操作は再生位置のステップだけの枠を変える（全ステップにそろえるのは LAY-01 のボタン）。録画を選ぶと、設定パネルはそのステップの「録画の枠」の欄を開く。枠の中のドラッグで移動、四隅のハンドルで縦横比を保ったまま拡大縮小、四辺の中央のハンドルで縦横比を変える（切り取りになる）。拡大縮小は「中心固定」（既定）と「隅固定」（反対側の角・辺を固定）を切り替えられる。移動・拡大縮小とも、出力の中心線と画面の上下左右の辺に吸着する（Altで解除）。選択中は矢印キーで10px（Shiftで1px）ずつ動かせる。移動では枠の大きさを変えず、ズームの枠は録画の内側だけを動く。プレビューの外(タイムライン・再生操作を含む。設定パネルと操作の帯は除く)のクリックと再生の開始でも編集を終える |
| LAY-09 | 「余白なし」をオンにすると余白を0にして中央に置く。オフにすると、オンにする前の余白に戻す（アプリを閉じるまで覚える） |
| LAY-10 | 録画がないときも、録画を置く場所は黒で示す（影の有無によらない）。その中央に出す「録画・画像を追加…」のボタン(押すとファイルの選択を開く。確認は挟まない)か、サムネイル列の「全体」より下を埋める「＋ 録画・画像」のボタンで録画を追加できる。このボタンはステップが1つもないとき（録画を消して空になったときも）大きくし、ふだんはサムネイル列の下端に「全体」と同じ高さで「＋ 録画・画像」と出す。画像も同じく追加できる。mp4・画像をサムネイル列にドロップしても追加できる（ステップの有無によらない）。タイムラインの映像のレーンでは、空いた所の右クリックで末尾に、クリップの右クリックでそのステップの後ろに録画・画像を足せる。ステップがないとき、設定パネルは全体の設定を出す |

### 5.5 テロップと文字（TXT）

| ID | 要件 |
|---|---|
| TXT-01 | 各ステップにテロップ文を持つ。読み上げは既定でテロップと同じ文を読む(テロップを直すと読み上げも変わる)。読み上げの文を書き換えるとその文を読み、テロップと同じ文に戻すとまたテロップに合わせる。切り替えのチェックは置かない |
| TXT-02 | テロップは余白の値によらず表示する。位置（中心、画面側座標）と幅（文はこの幅で折り返す）は、プロジェクト共通の設定をステップごとに上書きできる。ステップの上書きはプロジェクト設定に戻せ、全ステップの上書きを一括で解除できる。録画の枠（余白）を変えると、位置を書いたテロップも枠との位置関係を保って動く（枠の中なら枠の中の、余白にあれば余白の中の同じ割合の位置） |
| TXT-03 | 位置を指定しなければ、録画の下の余白に収まるならその中央、収まらなければ画面の下寄りに置く。文字の背景の箱は既定で付けない。プロジェクトとステップごとに「なし／あり」を選べる。プレビュー上でテロップをドラッグして位置を変えられ、左右の中央、録画の下の余白の中央、録画の下辺、画面の下辺に吸着する。ドラッグで変わるのはそのステップの位置で、ステップの詳細の「この位置を共通にする」で全ステップ共通にできる。PowerPoint と同じく、文字のクリックでその場で文字を入力でき（ステップの詳細の入力欄と同じ値）、枠（文字の外側の縁）のクリックで枠を選ぶ。どちらもドラッグなら移動。入力中は Enter で改行、Esc か外のクリックで入力を終えて枠を選んだ状態に戻る。どちらでもそのステップのテロップの設定へ移る |
| TXT-04 | 自動で折り返す。ユーザーが入れた改行も反映する |
| TXT-05 | フォントサイズはテロップごとに指定でき、全体一括でも変更できる。自動縮小とページ分けはしない |
| TXT-06 | 表示時間はユーザーが指定できる。既定はステップの全期間 |
| TXT-07 | フォントはOSにあるものから選ぶ（名前を打ち込むと前方一致で絞り込む。UI-21） |
| TXT-08 | テロップをSRTファイルとして出力できる |

### 5.6 読み上げ（TTS）

| ID | 要件 |
|---|---|
| TTS-01 | OS標準の音声合成を本体に内蔵し、既定のエンジンとする（WindowsはWindows標準の音声合成） |
| TTS-02 | 読み上げエンジンはプラグインで追加できる。内蔵エンジンもプラグインと同じインターフェースで実装する |
| TTS-03 | インターフェースの入力は「文章、声、パラメータ（速度、ピッチ、音量など）」、出力は「wavと長さ」 |
| TTS-04 | エンジンは使える声と、調整できるパラメータの一覧を返す |
| TTS-05 | 生成した音声はキャッシュする。エンジン名、エンジンのバージョン、声、パラメータ、文章（辞書適用後）が一致すれば再利用する。キャッシュの使用量（上限 500MB）をアプリの設定に出し、確認のうえ消せる |
| TTS-06 | 読みの辞書は本体の機能とする。エンジンに渡す前に文字列を置き換え、テロップの表示は変えない。語と読みは行ごとの 2 つの欄で入れる（書き方の決まりを利用者に守らせない） |
| TTS-07 | 辞書は全体共通とプロジェクト単位の両方を持つ |
| TTS-08 | エンジン側の辞書（アクセント指定など）は、各エンジンの機能として使えればよい（本体は関与しない） |
| TTS-09 | エンジン未起動、タイムアウト、中断を扱い、ユーザーに分かる形で通知する |
| TTS-10 | エンジンは必要なクレジット表記を返せる。本体は書き出し時にそれを通知する（組み込みの VOICEVOX・Azure AI Speech は返さず、各サービスの規約の確認を促すだけにする。TTS-14） |
| TTS-11 | OS標準音声を使う場合、商用利用の条件は利用者が確認するよう案内を表示する（11章の未確認事項） |
| TTS-12 | VOICEVOX互換エンジンに接続できる。ローカルで動くエンジンのHTTP APIに接続し、exeパスの指定と自動起動に対応する。エンジン・声は同梱しない（YMM4と同じ方式）。アプリに組み込むが既定では使えず、アプリの設定で、VOICEVOXと使う声（キャラクター）ごとの利用規約の確認に同意して有効にしたときだけ選べる（[decisions/20261111-external-tts.md](decisions/20261111-external-tts.md)） |
| TTS-13 | Azure AI Speech に接続できる。ユーザー自身の契約の鍵とリージョンでREST APIを呼ぶ（SDKは使わない）。鍵はOSの仕組みで暗号化してアプリの設定に置き、画面とプロジェクトファイルには出さない。既定では使えず、アプリの設定で、利用規約・料金がユーザーの責任であることと、読み上げる文がMicrosoftに送られることに同意して有効にしたときだけ選べる（[decisions/20261111-external-tts.md](decisions/20261111-external-tts.md)） |
| TTS-14 | エンジンはプロジェクト全体で1つ選ぶ（全体の設定の「読み上げ」）。エンジンを替えたら声の指定を外す。プロジェクトが指定したエンジンを、開いたパソコンで有効にしていなければ、OS標準の声で代わりに読み、そのことを知らせる。VOICEVOX・Azure を使った書き出しでは、それぞれの規約（と料金）を確認するよう知らせる。クレジット表記の例など、各サービスの規約の中身はアプリに書かない |

### 5.8 ズーム（ZM）

| ID | 要件 |
|---|---|
| ZM-01 | 指定した範囲へズームイン・ズームアウトする |
| ZM-02 | ズーム範囲はユーザーがUIで指定する（自動ズームはしない） |
| ZM-03 | 開始時刻と終了時刻をステップ内の出力時刻で指定する。この区間は拡大したまま保ち、拡大の動きは開始の手前、縮小の動きは終了の後ろで行う。間が1.5秒未満のズームどうしは戻らずに次の範囲へ移る（[decisions/20261031-zoom-model.md](decisions/20261031-zoom-model.md)） |
| ZM-04 | ズーム中の映像は「止める（保持）」「拡縮時のみ（拡大・縮小の動きの間だけ止める）」「止めない（流す）」から、並べたボタンで選べる。既定は止める |
| ZM-05 | 動きの時間（ズームにかかる時間）は既定で倍率から自動で決め（0.6 + 0.55 × ln(倍率) 秒）、秒数で指定もできる（0で動きなし）。範囲の枠は「必ず見せる範囲」で、プレビュー上の操作は LAY-08 と同じ（枠の外のクリックかEscで確定）。倍率・枠の幅と高さ・中心は数値でも入力できる。倍率と中心を保ったまま枠を録画の縦横比に戻せる |
| ZM-06 | ズーム中に移動できる。枠（キーフレーム）を任意の数置くと、枠と枠の間を一定の速さで移る。枠はタイムラインに◆で示し、時刻を変えられる。枠の大きさを変えるとき、全部の枠の大きさをそろえられる（既定オン。中心は保つ） |
| ZM-07 | 既定では枠の範囲だけを映す（録画を描く領域が枠の縦横比になり、余白の内側の中央に置く）。テロップの位置は変えない。「録画の縦横比を保つ」を選ぶと、枠を録画の縦横比に広げて表示する |
| ZM-08 | タイムラインのズームをクリックすると、プレビューで範囲の編集を始める（再生位置は動かさない）。編集中にタイムラインでシークしても編集を続け、プレビューはズームせずに枠を出す。再生を始めると（Space を含む）編集を終える。ズームの帯をダブルクリックすると、その時刻に枠を足す。ズームはコピー・切り取り・貼り付けできる（Ctrl+C／Ctrl+X／Ctrl+V、右クリック）。録画の大きさが違えば枠を換算する |
| ZM-09 | ズームの開始・終了をタイムライン・設定パネルで動かすと、再生位置を合わせる。映像を「止める」ズームは常に開始の時刻、「拡縮時のみ」「止めない」ズームは開始を動かせば開始・終了を動かせば終了の時刻。帯ごと動かすときは開始の時刻 |

### 5.9 ポインター・図形（ANN）

| ID | 要件 |
|---|---|
| ANN-01 | 擬似ポインターを後から付けられる。録画に映っていたカーソルは使わない |
| ANN-02 | 蛍光ペンを後から付けられる。蛍光ペンはポインターの見た目の 1 つ（動きに沿って線を引く） |
| ANN-03 | どちらも「フリーハンド」と「直線」の2つのモードを持つ |
| ANN-04 | フリーハンド：マウスの動きを、時刻付きの軌跡として記録する |
| ANN-05 | 直線：始点の位置と時刻、終点の位置と時刻を指定する。水平方向にスナップする（Alt で解除） |
| ANN-06 | どちらも映像側座標で持ち、ズームに追従する |
| ANN-07 | ポインターの見た目は 矢印のカーソル・丸・輪・蛍光ペン・ユーザーの画像（画像の左上を指す点にする）から、アイコンを並べたボタンで選ぶ。その下に選んだ見た目の設定（大きさ・色）を出す。着いたときにクリックの波紋を出せる（蛍光ペンを除く） |
| ANN-08 | 蛍光ペンの色、太さ、不透明度を指定できる |
| ANN-09 | 表示・非表示の切り替えにフェードイン・フェードアウトとフラッシュ（点滅）を使える。並べたボタンで選び、フェードは長さ、フラッシュは長さと点滅の回数を指定できる。点滅は長さの中で均等に繰り返す（長さを出ている間と同じにすれば、出ている間ずっと点滅する）。長さは出ている間を上限にし、現れ方と消え方が重なってもよい（重なる時刻は暗い方） |
| ANN-10 | 四角を置ける。線の色・太さ（0 で線なし）、塗りの色と不透明度（0 で枠だけ）、角の丸みを指定できる。線・塗りはチェックで出す・消すを切り替える。中にユーザーの画像ファイル（png・jpg・webp）を入れられる（線は画像の枠になり、透明な所には塗りが見える。入れたときに画像の縦横比に合わせる） |
| ANN-11 | 矢印を置ける。始点・終点、色、太さ、矢じりの大きさを指定できる |
| ANN-12 | 文字を好きな位置に置ける（枠の幅で折り返す）。フォント・大きさ・色・揃え・背景の塗り（チェックで出す・消す）を指定できる |
| ANN-13 | （ANN-10 に統合: 画像は四角の中身） |
| ANN-14 | 図形（ANN-10〜12）は図形ごとに座標の基準を並べたボタン（録画に追従／画面に固定）で選べる。既定は映像側（ズームに追従し、録画の領域の中だけに描く）。「画面に固定」にするとズームしても動かず、背景や録画と背景にまたがる位置にも置ける。切り替えても見えている位置と大きさは変わらない。録画に追従する図形が録画の外にはみ出したら（はみ出た所は描かれない）、設定パネル（畳んでいても見える所）とタイムラインの帯（赤い縞と「⚠ 録画外にはみ出し」）に印を出し、プレビューで選んだときの枠を赤にする。出ている間（開始・終了）と出入りの効果は ANN-09 と同じ。重なりの順を変えられる |
| ANN-15 | プレビュー上でクリックして選び、四角・文字は枠の取っ手（中心固定／隅固定を切り替えられる）、ポインター・矢印は両端の取っ手で直せる。ポインターは水平、矢印は 45 度ごとに吸着する（Alt で吸着しない）。タイムラインの「オブジェクト」の段で出ている間を直せる（重なるものは行を分ける）。始まりを動かすと再生位置を合わせる。停止中は、選んでいるオブジェクトをフェード・点滅で見えない時刻でも出す。設定パネルでは項目をいくつでも開いたままにできる（タイムライン・プレビューで選ぶとそれだけを開き、設定パネルで開いたものは足す） |
| ANN-16 | ズーム・読み上げ・オブジェクトはコピー・切り取り・貼り付けできる（Ctrl+C／Ctrl+X／Ctrl+V、タイムラインの帯の右クリック、レーンの空いた所の右クリックの「ここに貼り付け」）。貼ると再生位置（右クリックならその時刻）が始まりになる。録画の大きさが違えば座標を換算する。テロップの文を読む読み上げは、その文を書いた読み上げとして写す |
| ANN-17 | ステップを分割したとき、分割点をまたいで出ているオブジェクトは前半のステップの終わりまで出す |

### 5.13 編集画面（UI）

| ID | 要件 |
|---|---|
| UI-01 | 左からサムネイル列、プレビューとタイムライン、設定パネルの順に置く(選ぶ → プレビューで直す → 設定パネルで詰める)。プレビューの真下の帯(2 段)の上の段に、テロップ・ズーム・オブジェクト(ポインター・蛍光ペン・四角・矢印・テキスト・画像)の追加をアイコンと名前のボタンで並べ、そこから始められる(再生中・枠の編集中は押せない)。テロップのボタンは、そのステップにテロップがなければ全期間のテロップを作って入力を始める(再生位置がテロップの区間の外なら押せない)。サムネイル列はいちばん上の「全体」とステップごとのサムネイルで、押すと設定パネルが全体の設定かそのステップの詳細（録画・速度／文／ズームの開け閉めできる欄）になる。サムネイルの横に ID・長さとテロップの文を出し、列が狭ければサムネイルだけにしてマウスを重ねたときに文を出す。全ステップ共通の設定は全体の設定に置く。要素を選ぶとそれを直す画面に切り替わり、その欄を開く |

| UI-08 | シークバー（タイムライン）の操作に、プレビューの表示が遅れず追従する |

| UI-17 | プレビュー上でテロップの左右の端をドラッグして幅を変えられる（中心固定。録画と画面の左右の辺に吸着） |
| UI-18 | 再生でステップの切れ目をまたいでも映像が止まらない。続いた区間（同じ録画で前の Out = 次の In）は1本のデコードで読み続け、切った箇所は切れ目の2秒前から次の区間をデコードしておく |
| UI-20 | 書き出しが終わった知らせに、書き出したファイルのフォルダーを開くボタンを付ける。書き出し中は書き出しのボタンが「中止 n%」になり、押すと中止する（途中のファイルは残さない） |
| UI-21 | フォント（テロップ・テキスト）は名前を打ち込め、打っている間は OS のフォントを絞り込んで候補に出す（前方一致を先に、途中に含むものを後に）。英語の名前に加え、よく使う日本語フォントは日本語の名前（游ゴシック・メイリオなど）でも探せる |
| UI-22 | 設定パネルの数値の欄は、書いていない値も既定値を普通の文字で出す（消して欄を離れると既定値に戻る）。入力中は打った文字を書き換えない（消して空にしても既定値を入れず、丸めた値で置き換えない）。出力の幅・高さは、空や小さすぎる値の間は直前の大きさのまま |
| UI-23 | 画面の文字は Windows の Fluent の段に合わせる（本文・ボタン・入力欄 14px、欄の見出しは 12px）。画面全体の表示の大きさを Ctrl+プラス／Ctrl+マイナスで段階（80〜200%）で変え、Ctrl+0 で等倍に戻す。アプリの設定でも % の数字（50〜300）で入れられる。プレビューの横などに −／＋ のボタンは置かない。倍率はアプリの設定に覚える。書き出す映像には効かない（[決定記録](decisions/20261113-ui-text-size.md)） |

| UI-19 | プロジェクトによらないアプリの設定（画面の言語、表示の大きさ、プロジェクトの保存先、新しい版の確認、読み上げエンジンと読み上げのキャッシュ、キー操作の割り当て）を持ち、ヘッダーの「設定」から変えられる。左のメニューで区分（一般・読み上げ・キー操作）を切り替える（[決定記録](decisions/20261109-header-and-app-settings.md)）。キー操作の一覧の「キー操作を変更…」からも開ける。キーの割り当ては、ボタンを押してから新しいキーを押す。同じキーがほかの操作にあればそちらを外し、アプリが使う Ctrl のキーは断る。プロジェクトのファイルには入れない |

## 6. 座標と時間のルール

| 要素 | 座標系 | 時間の基準 |
|---|---|---|
| ポインター | 映像側（ズームに追従） | ステップ内の出力時刻 |
| 図形（四角・矢印・文字） | 映像側（ズームに追従。既定）か画面側（固定）を図形ごとに選ぶ | ステップ内の出力時刻 |
| テロップ | 画面側（固定） | ステップ内の出力時刻 |
| ズーム範囲 | 映像側 | ステップ内の出力時刻 |

座標系は要素の種類ごとに固定する。図形だけは、背景に置く・録画と背景にまたがって置く用途のため、図形ごとに選べる。

| NF-05 | エンコード | OSまたはハードウェアのエンコーダーを使う。ハードウェアエンコーダーがない環境での代替手段を用意する（11章） |

## 8. 決定の経緯

主要な決定は [docs/decisions/](decisions/) に個別の記録がある（構成モデル・座標系・エンコーダー・読み上げ・ライセンス）。UI基盤（Electron）・MVP範囲・プロジェクトファイルの形も決定済み。

| 論点 | 決定 | 理由・根拠 |
|---|---|---|
| 構成モデル | ステップ単位 | 手順書の構造に合う。汎用的なタイムライン編集より単純で、AIにも指示しやすい |
| ステップの作り方 | 1本の録画から切り分ける | ステップごとに録画し直す手間をなくす |
| 時間の基準 | ステップ内の出力時刻 | 保持で尺が伸びても位置がずれない |
| 保持とズーム中の静止 | 同じ機能にまとめる | 実装を二重にしない |
| 使わない区間 | カットが既定。早送りステップも使える | 待ち時間など、経過を見せたい場面に対応 |
| 映像が読み上げより長い場合 | そのまま再生し、必要ならユーザーが分割して捨てる | 自動で速度を変えると意図しない速さになる |
| 1ステップの読み上げ | 複数置ける（開始時刻つき） | 1文を分けて読み、間にズームを入れたい。ステップを分けると同じテロップを二重に持つことになる |
| 座標系 | 要素の種類ごとに固定 | 要素ごとに選ばせると実装と操作が複雑になる |
| 図形 | 四角（画像を入れられる）・矢印・文字。既定は映像側座標、図形ごとに「画面に固定」も選べる | 手順書の強調は録画の中の物を指すものが大半なので既定はズームに追従。背景に置く見出し・録画の外から指す矢印のため画面側も選べる（[decisions/20261109-objects.md](decisions/20261109-objects.md)） |
| 録画の枠（余白） | 全体の設定をステップごとに上書き | 表紙の画像だけ全画面にするなど、例外のステップだけ変えたい |
| 読み上げ | OS標準を内蔵し、プラグインで拡張 | プラグインがなくても全機能が動く必要がある（C6） |
| 読みの辞書 | 本体の機能 | エンジンを問わず同じように効く |
| VOICEVOX・Azure AI Speech 対応 | アプリに組み込み、既定では使えない。ユーザーが規約・費用の確認に同意して有効にし、エンジン・声・鍵はユーザーが用意する。VOICEVOXはエンジンを同梱しない | 使い方の責任をユーザー側に置く。VOICEVOXはYMM4に前例あり。キャラクターごとの規約とサイズのため |
| エンコーダー | OS／ハードウェアのエンコーダー | GPL（x264など）を避けるため。OpenScreenに前例あり |
| UI基盤 | Electron/Tauriも可 | 最近の画面録画系ツール（OpenScreen、Cap）が採用 |
| 出力設定 | OpenScreen相当 | Clipchampは選択肢が少なすぎ、Shotcutは細かすぎる |
| プロジェクト管理 | Shotcut相当 | 相対パスと絶対パスの自動判定、復旧専用の自動保存 |
| 公開ライセンス | Apache-2.0 | 無償で商用利用できるライセンスにするため |
| 配布 | GitHub Releases、コード署名は後回し | 個人配布のYMM4も未署名の警告画面を通過して利用されている |
