# メニューバーを隠し、操作はヘッダーに集め、アプリの設定を足す(2026-11-09 決定)

編集画面のいちばん上(メニューバーとヘッダー)の決定。何を置き、プロジェクト名をどう見せ、プロジェクトによらない設定(アプリの設定)をどこに持つか。設定パネル・サムネイル列の置き場所は [20261108-step-drilldown-ui.md](20261108-step-drilldown-ui.md)。

## 決定

- **メニューバー**: Windows では出さない(`setMenuBarVisibility(false)`)。メニュー自体は残し、Ctrl+N/O/S/E/Z/Shift+Z/`/` のキーと、コピー・切り取り・貼り付け(role)、開発者ツール・再読み込み(View の role)と画面全体の表示の大きさ([20261113-ui-text-size.md](20261113-ui-text-size.md))に使う。Mac はメニューが画面上端の別の場所にあるのでそのまま
- **ヘッダー**: 高さ約 40px。ボタンは小さいアイコン(名前とキーはツールチップ)。ファイルと書き出しはアイコンだけでは分かりにくいので文字も添える(ユーザーの指摘)。左右を同じ幅の列にし、プロジェクトの名前をウィンドウの中央に置く
  - 左: ファイル(押すと新規・開く・保存のメニュー)、元に戻す・やり直し
  - 真ん中: プロジェクトの名前(ファイル名から `.stepcut.json` を除く)と、未保存なら ●。全体のパスはツールチップ
  - 右: 設定(歯車。アプリの設定)、書き出し(強調色)
- **名前の変更**: ヘッダーの名前をクリックするとその場で入力できる。保存済みなら同じフォルダーでファイル名を変える(素材のパスは相対なので変わらない。同じ名前のファイルがあれば変えない)
- **新しいプロジェクトの保存**: 「保存」を押すと、まずヘッダーの名前の入力になる。入れた名前で、アプリの設定の保存先にそのまま保存する。保存先を決めていない・同じ名前のファイルがあるときは、その名前を入れた保存のダイアログを出す
- 「名前を付けて保存」は置かない。録画の追加はヘッダーに置かない(サムネイル列の ＋ とドロップ)
- ウィンドウのタイトル(タスクバー)は「● 名前 — StepCut」
- **アプリの設定**: ヘッダーの歯車でダイアログを開く。変えたらすぐ保存する
  - 左に区分のメニュー(一般 / 読み上げエンジン / キー操作)、右に選んだ区分の中身を出す。ダイアログの高さは固定し、右だけがスクロールする。メニューは上下キー・Home・End でも移れる。歯車から開くと毎回「一般」から(前の区分は覚えない)。区分は中身ができてから足す(空の区分は作らない)
  - 一般: 言語(OS に合わせる / 日本語 / English。切り替えると開いている画面の文言がその場で変わる)、表示の大きさ、プロジェクトの保存先(新しいプロジェクトを保存するときと、開くときに最初に出すフォルダー)
  - 読み上げエンジン: VOICEVOX 互換エンジンと Azure AI Speech([20261111-external-tts.md](20261111-external-tts.md))。全体の設定の読み上げの「読み上げエンジンの設定…」からこの区分で開く
  - キー操作の割り当て: 再生・シーク・分割・ズームの追加・消音・中心固定/隅固定・全画面・削除。ボタンを押してから新しいキーを押す。同じキーがほかの操作にあればそちらを外し、メニューが受け持つ Ctrl のキー(ファイル・元に戻す・コピーなど)と Esc は断る。既定から変えたものだけを保存する。キー操作の一覧の「キー操作を変更…」からこの区分で開く
  - 保存先はユーザーデータのフォルダーの `settings.json`(メインプロセスが持つ)
- **知らせとプロジェクトの問題**: ヘッダーの下の帯 1 か所にまとめる(以前は知らせが上端、問題の一覧が下端で、見る場所が分かれていた)。知らせ(保存・書き出しの結果など)も問題(検証のエラー・警告、読めない録画)も × で閉じられる。問題は閉じたときの中身を覚え、中身が変わったらまた出す(問題があっても進めてよい場合に、消せない帯が邪魔にならないように。ユーザーの指摘)
- **ウィンドウの最小幅**: サムネイル列(56px)と設定パネル(160px)の最小幅に、再生操作の帯が重ならずに並ぶ幅(560px。真ん中のボタン群を中央に置いたまま、左の時刻と右の速度・消音・全画面が重ならない幅に余白)を足した 786px。パネルを広げたままウィンドウを狭めたときは、設定パネル → サムネイル列の順に縮めて表示する(覚えている幅は変えない)

## 理由

- メニューバーの項目はほぼヘッダーと重複していた。重複をなくし、画面の縦を空ける(ユーザーの指摘)
- メニューを丸ごと消すとキー操作(accelerator)とコピー・貼り付けの役割が効かなくなるため、隠すだけにする
- 名前をウィンドウの中央に置くには、左右のボタンの幅を抑える必要がある。文字をなくし、新規・開く・保存を 1 つのメニューにまとめ、名前を付けて保存と録画の追加を外して、左右とも 2〜3 個にした(ユーザーの指摘)
- 名前を付けて保存の主な用途は名前を変えることなので、名前のクリックで足りる。別の場所への複製は OS のファイル操作で足りる
- 書き出しは最後にする操作なので右端に離し、ほかの操作と取り違えないよう色を変える
- 保存先は開く・保存のダイアログ(メインプロセス)が使うので、レンダラーの localStorage ではなくメインのファイルに置く
- アプリの設定を区分に分けるのは、項目が増えて 1 列では長くなったため(キー操作の表だけで 15 行あり、上の項目がスクロールで隠れた。ユーザーの指摘)。区分は今後(書き出しなど)増えるので、横に並べるタブより縦のメニューにした。Windows 11 の設定・VS Code と同じ形

## 不採用案と理由(逆戻りガード)

- **メニューを消す(`Menu.setApplicationMenu(null)` / `removeMenu()`)** — Ctrl+S などのキーとコピー・貼り付けが効かなくなる
- **Alt で出す自動で隠れるメニューバー(`autoHideMenuBar`)** — Alt を押すと急に出てきて画面がずれる。ヘッダーに全部あるので出す理由がない
- **アイコンの下に文字を付けたボタンを並べる** — 左右の幅が違い、名前をウィンドウの中央に置けない。ヘッダーの高さも増える
- **名前の下にフォルダーを小さく出す** — 2 行になってヘッダーが高くなる。場所はツールチップで足りる
- **名前を付けて保存を残す** — 名前の変更はヘッダーの名前で足りる
- **プロジェクト名をウィンドウのタイトルだけに出す** — Windows のタイトルバーは目に入りにくく、未保存の印が見落とされる
- **アプリの設定の区分を上のタブにする** — 3 つなら足りるが、区分が増えると幅が足りず、日本語と英語で長さも変わる
- **アプリの設定を 1 ページのまま見出しと目次を付ける / キー操作だけ別のダイアログにする** — 前者は長いままで、後者は設定の場所が 2 つに分かれる
- **前に開いていた区分を覚える** — 覚える場所が要る。指定して開く経路(キー操作の一覧・読み上げ)は区分を直接開くので、歯車からは「一般」で足りる
- **アプリの設定をレンダラーの localStorage に置く** — 保存・開くのダイアログ(メイン)から読めない。設定ファイルとして人が直すこともできない

## 前提と再検討の条件

- メニューにしかない操作を足すときは、ヘッダーかキー操作の一覧に置き場所を作る(メニューバーは見えないため)
- アプリの設定の候補(未実装): 書き出しの保存先の既定、ハードウェアエンコーダーを使うか(この 2 つは「書き出し」の区分を足して置く)、パネルの幅などの表示を初期状態に戻す(一般)。足すときはこの記録を書き換える
