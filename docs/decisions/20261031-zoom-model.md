# ズームの帯は「拡大したまま保つ区間」、動きは帯の外で倍率から自動(2026-10-31 決定)

ズーム(ZM-03〜05、U-05)の時刻の意味、動きの時間、範囲の指定方法についての決定。OpenScreen と Screen Studio の仕様に合わせた。

## 決定

- `start` 〜 `end` は拡大したまま保つ区間。拡大の動きは `start` の手前、縮小の動きは `end` の後ろで行う。ステップの外にはみ出す分は切り詰める
- 動きの秒数は倍率から決める: 0.6 + 0.55 × ln(倍率) 秒(1.8 倍で約 0.92 秒、2 倍で約 0.98 秒)。`transition` を書けば上書き、`0` なら動きなしで切り替える(UI は「動きなしで切り替え」のチェック)
- 前のズームの終わりから次のズームの始まりまで 1.5 秒未満なら、いったん戻らずに次の範囲へ移る
- ズーム中は既定で映像を止める(`hold` の既定を `true` にした)
- 範囲は枠(`rect`)で決める。枠は「必ず見せる範囲」で、表示の縦横比と違うときは中心を保って上下か左右を広げて表示する(プレビューでは実際に見える範囲を点線で示す)。倍率は枠の大きさから決まる
- プレビューの枠の操作は録画の枠と共通([20261031-margin-layout.md](20261031-margin-layout.md))。右カラムで倍率・枠の幅と高さ・中心を数値でも入力できる(倍率を変えると中心と縦横比を保って枠が変わる)
- 追加: Z キー(再生位置に、帯の長さ 2 秒)、ズームのレーンのドラッグ、プレビューの右クリック

## 理由

- 調査(2026-10-31): OpenScreen はズームの帯を拡大したまま保つ区間とし、拡大の動きを帯の手前、縮小を後ろに置く(`src/lib/ai-edition/timeline/zoom-transitions.ts`)。動きの時間はズームごとの設定ではなく倍率から決める(`src/lib/zoomMath/constants.ts`: 600 + 550 × ln(倍率) ms)。間が 1.5 秒未満なら横移動する。Z キーで再生位置に追加する(`src/lib/shortcuts.ts`)。Screen Studio はズームごとに「Instant Animation」(動きなし)を選べる(公式ガイド Instant Zoom)
- 帯の内側で動くと「帯の長さ = 拡大して見える長さ」にならず、旧 UI の「切り替え(秒)」が分かりにくかった
- 手順書では拡大した場面を読ませたいので、映像を止める方が既定に合う(ユーザー判断)

## 不採用案と理由(逆戻りガード)

- **帯の内側で拡大・縮小する(旧仕様)** — 帯の長さと拡大して見える長さが一致しない
- **ズームごとに動きの秒数を設定する(旧 UI の「切り替え(秒)」、既定 0.4 秒)** — 意味が伝わらず、速すぎた。倍率から自動にする
- **倍率の段階ボタン(OpenScreen の 6 段階)と中心の点で指定する** — ユーザーの指定で、範囲の枠で決める方式にした
- **範囲を表示の縦横比に強制する(旧仕様)** — 四辺のハンドルで縦横比を変えられない。「必ず見せる範囲」として広げて表示する

## 前提と再検討の条件

- 既存のプロジェクトで `hold` を書いていないズームは映像を止めるようになる(M1 段階なので許容)
- `start` の手前に動きの時間がないズーム(ステップの先頭付近)は、ステップの始まりで拡大した状態から始まる
