# 編集画面は動画編集アプリ風のタイムラインを中心にする(2026-10-29 決定)

M1 を触ったユーザーのフィードバックを受けて、編集画面の操作体系を決めた。プレビューのシーク・再生速度・キー操作、タイムライン、画面構成、ズームの持ち方を含む。データ構造(ステップ単位、時刻はステップ内の出力時刻)は [20261026-step-based-model.md](20261026-step-based-model.md) のまま変えない。

## 決定

- 操作感は一般的な動画編集アプリ(Premiere Pro、Final Cut Pro、DaVinci Resolve)に合わせる
- 画面: 左にサムネイル列と設定パネル、右にプレビューとタイムライン → [20261108-step-drilldown-ui.md](20261108-step-drilldown-ui.md)
- タイムラインのトラックは固定(映像・テロップ・読み上げ・ズーム)。任意のトラック追加や重ね合わせはしない
  - 映像トラックは 1 クリップ = 1 ステップ。サムネイルを並べ、保持を斜線で示す
  - クリップ端のドラッグは In/Out の変更(録画の続き・手前を見せる)。録画の端で止まる。後続のステップは詰めて動く
  - In を動かしたら、ステップ内の要素の時刻を同じ分ずらして映像の中身との対応を保つ
  - 保持は端ドラッグとは別の操作(右クリック「＋ ここに保持」)。保持の端ドラッグで長さを変える
  - テロップ・読み上げ・ズーム・オブジェクトの開始・終了はドラッグで変える。ステップの外には出せない
  - 読み上げ・ズーム・オブジェクトの帯は Ctrl+クリックでまとめて選び、まとめてドラッグで動かせる(どれもステップの中に収まる範囲で、同じだけずらす)。端のドラッグでは、選んだものすべての同じ側の端を同じだけ動かす(読み上げは長さが決まっているので変えない)
  - 映像のクリップに、ステップのフェードイン・フェードアウトの区間を黒の三角と斜めの線で示す(保持の斜線と同じく、クリップの上で見て分かるように)
  - 開始・終了を動かすと(設定パネルの数値でも)再生位置を合わせ、動かした所の映像を見せる。読み上げ・オブジェクトは開始。ズームは、映像を止めるズームなら常に開始(止めた所の映像)、それ以外は動かした端(帯ごと動かすときは開始)
  - 目盛り・全トラックで同じ「時刻→ピクセル」変換を使う(別々に描いたシークバーと帯がずれる問題を構造的に防ぐ)。独立したシークバーは置かない
- ズームはステップに属したまま(時刻はステップ内の出力時刻)。UI ではステップを意識させず、作成した時刻のステップに入れる。プレビュー上の右クリックからも作れる。帯の意味と動き → [20261031-zoom-model.md](20261031-zoom-model.md)
- シーク(目盛り・レーンの空いているところ・レーンの下の空きのクリックとドラッグ)は、ステップの切れ目と、テロップ・読み上げ・ズーム・保持・オブジェクトの始まりと終わりに吸着する(8px 以内、Shift で解除)
- レーン上の要素(テロップ・読み上げ・ズーム・オブジェクト)はクリックで選んでも再生位置を動かさない(今の再生位置へ要素を動かす操作が多く、選ぶたびに再生位置が動くと困る)。ダブルクリックで再生位置をその始まりへ移す(ズームのダブルクリックは枠の追加のまま)。設定パネルで要素を選んだときは始まりへ移す。映像クリップは、再生位置がそのステップの外のときだけ始まりへ移す(クリップは中のどこでも押せるので、中なら見ている場面を変えない)。レーンの空いた所・目盛り・レーンの下の空きでシークする
- 帯の端を動かすと再生位置を合わせる: ズームは設定に応じて開始か終了、読み上げは開始(長さは決まっている)、オブジェクトは動かした端
- ズーム・読み上げ・オブジェクトは、帯の右クリックでコピー・切り取り・削除、レーンの空いた所の右クリックでその時刻に作る・貼り付ける(Ctrl+C / Ctrl+X / Ctrl+V は再生位置に貼る)。コピーしたものはアプリの中に最後の 1 つだけ持つ
- 映像の段の見出しに、録画の音を全体で消す・鳴らすボタンを置く。ステップだけ消すのは映像クリップの右クリック
- 横のホイール(チルト・タッチパッド)はその向きにタイムラインをスクロールする
- 再生操作は一般的な動画プレイヤーに合わせ、中央に先頭・前のステップ・1 秒戻る・再生/停止・1 秒進む・次のステップ・末尾のアイコン、右に再生速度・消音・全画面表示を置く
- キーのある操作は、右クリックメニューの右側とボタンのツールチップにキーを書く
- 保持の区間も再生中に時刻とズームの動きが進むよう、再生はデコードと描画を分ける(デコーダーは同じフレームが続く間は何も返さないため、描画を毎フレーム別に行う)
- 再生のデコードは「続いた区間」(同じ録画で前のステップの Out = 次の In)ごとに 1 本で読み続ける。本当に切った箇所(録画が違う・区間が飛ぶ)は、切れ目の 2 秒前から次の区間を別のデコーダーで読み始めておく(先読み)。ステップごとにデコーダーを作り直すと、次の区間の手前のキーフレームから読み直しになり、切れ目で映像が止まって飛んだ(2026-11-05 計測: 約 0.3 秒)。一般的な編集ソフトの対処は先読み・編集用ファイル(プロキシ)・ハードウェアデコードで、変換の手間とディスクを使うプロキシは機能最小限(C7)に合わないので採らない
- 操作部品は対象ごとに置く: 再生操作・再生速度・消音・全画面はタイムラインの直上のバー、プレビュー上の操作(枠の編集中だけの切り替え、表示倍率)はプレビューの映像の真下の帯、キー操作の一覧の ? はヘッダー(アプリの設定の左)、タイムラインの拡大縮小(−/+/全体)は目盛りとトラック名が交わる左上の角(アイコン)。Premiere・Final Cut Pro もプレビューとタイムラインの拡大縮小を各パネルに持つ。映像の真下の帯は常に高さを確保し(編集を始めても映像の大きさが変わらない)、ウインドウが縦に余ると帯と再生操作の間が空く
- プレビューの上に操作の説明(hint)を重ねない。操作はカーソルの形、枠・取っ手・ボタンのツールチップ、キー操作の一覧(Ctrl+/・ヘッダーの ?)で伝える。Figma・PowerPoint・Premiere も、修飾キーなど見て分からない操作はツールチップとショートカット一覧で示す
- 枠の編集(ズーム・録画)は、プレビューの外(再生操作を含む)のクリックと再生の開始(Space を含む)でも終える。設定パネル・操作の帯・タイムラインは除く(数値で直す・枠を足す・シークしながら枠を見比べるため。タイムラインで別の要素を選べば終わる)。編集中にシークしても、プレビューはズームせずに枠を出す。枠はズームの帯のダブルクリックでその時刻に、操作の帯の「再生位置に枠を追加」で再生位置に足す
- プレビューと操作の帯はひとまとまりとして上下中央に置く
- 左カラムの「ステップを追加」(録画全体を末尾に足す)はやめた。録画全体はツールバーの「録画を追加」で足す
- ステップの並び替えは頻度が低いので、左のサムネイルの右クリックメニューに置く
- プレビューの停止中の表示は、デコードを常に 1 本だけにし、その間の要求は最新 1 件にまとめる。デコード中は、タイムライン用の縮小フレームのうち近いものを仮に表示する
- 再生速度は ×0.5 / ×1 / ×1.5 / ×2 / ×3(プレビューのみ)。再生操作の欄で選ぶ。音声は速度に合わせて高さも変わる。逆再生は持たない
- キー操作(既定。Ctrl のキー以外はアプリの設定で割り当てを変えられる。メニューが受け持つ Ctrl のキーは OS の標準に合わせて固定)

| キー | 動作 |
|---|---|
| Space | 再生/停止 |
| ← / → | 1 秒移動 |
| Shift+← / → | 1 フレーム移動 |
| ↑ / ↓ | 前/次のステップ境界へ |
| Home / End | 先頭/末尾 |
| S | 再生ヘッドの位置でステップを分割 |
| Delete | タイムラインで選んだ要素を削除 |
| Z | 再生位置にズームを追加 |
| M | 消音 |
| F | プレビューの全画面表示 |
| C | 枠の拡大縮小の中心固定/隅固定を切り替える |
| Ctrl+C / Ctrl+X / Ctrl+V | 選んだズーム・読み上げ・オブジェクトをコピー・切り取りし、再生位置に貼る |
| Ctrl+/ | キー操作の一覧 |

## 理由

- 動画編集アプリの操作に慣れた人がそのまま使える
- シーク不具合の原因は計測で確認した。1080p・キーフレーム間隔 10 秒の録画で、1.5 秒のドラッグ中は描画 0 回、ドラッグ後に溜まった 31 回分のデコード(1 回 0.15〜0.4 秒)を順に処理し、最終位置の表示はドラッグ終了の約 7 秒後だった。デコード要求をまとめた後は、ドラッグ中も描画され、最終位置の表示はドラッグ終了の約 0.6 秒後
- トラックを固定にすれば、データはステップ単位のまま保てる(AI からの編集のしやすさを維持)
- ズームを全体の時刻で持つと、前のステップの読み上げが伸びたときに後ろのズームがすべてずれる
- ←→ を 1 秒、Shift+←→ を 1 フレームにしたのはユーザー指定。一般的なアプリ(←→ が 1 フレーム)とは逆

## 不採用案と理由(逆戻りガード)

- **タイムラインのシークで枠の編集を終える** — 時刻を変えながら枠の位置を見比べられない(ユーザーの指摘で、タイムラインの操作では終えないようにした)
- **タイムラインの要素を選ぶと、その始まりへ再生位置を移す** — 選んだものはすぐプレビューに出るが、今の再生位置へ要素を動かそうとして選ぶと再生位置が動いてしまう(一度採用し、ユーザーの指摘で戻した。始まりへはダブルクリックで移す)
- **J / K / L(逆方向・停止・再生、連打で速く)** — 再生と停止は Space、速さは再生操作の欄で足り、逆再生は手順書づくりで使わない(機能最小限 C7)。キーを減らして割り当ての変更を分かりやすくした
- **プレビューの上に操作の説明の帯を重ねる** — 映像の上部が隠れ、編集中だけ出る切り替えボタンも説明の中に埋もれた。ツールチップとキー操作の一覧に移した(2026-11-07)
- **HLS で内部配信してバッファリングする** — HLS はネットワーク配信用の分割形式で、ローカルファイルはもともと任意の位置を直接読める。遅さの原因はデコードで、配信形式では解決しない。分割には再エンコードも要る
- **ズームをプロジェクト全体の出力時刻で持つ** — 読み上げの長さが変わると後ろのズームがずれる(TIM-01 の理由と同じ)
- **ズームを録画(ソース)の時刻で持つ** — 保持・早送り・同じ区間の再利用で対応が曖昧になり、ズーム中の静止と相性が悪い
- **クリップ端を録画の外へ広げたら保持にする** — 録画の続きを見せる通常のトリムと区別できなくなる
- **任意トラックの汎用タイムライン** — C7 に反し、AI からの編集も複雑になる
- **逆方向の実再生(音声付き)** — WebCodecs で逆向きのデコードは重い。J は停止中の表示を時計に合わせて更新する方式にする

## 前提と再検討の条件

- 正確なフレームの更新は 1 回のデコード時間に縛られる(上の環境で毎秒 2〜3 回)。仮表示の縮小フレームで足りなければプロキシ(キーフレーム間隔の短い縮小版)を作る(NF-04)
