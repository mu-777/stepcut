# MVP は「切り分け・テロップ・読み上げ・ズーム・書き出し」と AI 編集の往復まで(2026-10-29 決定)

最初に作る範囲(要件 T-06)と、それ以降の段階分けについての決定。要件 5 章の ID ごとに、どの段階で入れるかを決める。

## 決定

3 段階に分ける。M1 を MVP とする。

| 段階 | 到達点 | 含める要件 |
|---|---|---|
| M1(MVP) | Windows で、1 本以上の録画をステップに切り分け、テロップと OS 標準の読み上げとズームを付けて mp4 と SRT を書き出せる。AI が JSON を編集すると、アプリが再読み込みする | PRJ-01, 02, 04, 05, 07 / STP-01〜08 / TIM-01〜05 / LAY-01〜07 / TXT-01〜06, 08 / TTS-01〜06, 09, 11(辞書はプロジェクト単位のみ) / AUD-01〜03 / ZM-01〜05 / STY-01, 02(テロップのみ) / OUT-01〜06 / AI-01, 02, 04〜07 |
| M2 | 強調表示と AI による座標指定 | ANN-01〜09(直線モードのみ)・ANN-10〜15(図形) / AI-03 / PRJ-03, 06 / STY(ポインター・蛍光ペン・図形) |
| M3 | 拡張と Mac | ANN のフリーハンド / TTS-02 の外部プラグイン読み込み・TTS-07 の全体辞書・TTS-10・TTS-12(VOICEVOX) / TXT-07(OS フォント一覧から選ぶ UI) / Mac 版 |

M1 の時点で、JSON の形(要件 T-05)は M2・M3 の要素も含めて決めておく。後から形を変えないため(C5)。

## 理由

- M1 だけで手順書動画の最小形(場面ごとの文字と音声、見せたい箇所の拡大)が完成し、mp4 と SRT が得られる
- ズームは手順書で細かい UI を見せるのに欠かせないため M1 に入れる(ユーザー判断)
- AI 連携(検証・CLI 書き出し・外部変更の検知)はこのアプリの存在理由(1.3)なので、M1 に入れる
- ポインター・蛍光ペンは軌跡の指定 UI とフレーム書き出し(AI-03)が要り、作業量が大きい。M1 の描画処理ができてから足しても構造は変わらない
- フリーハンドの記録、プラグインの読み込み、VOICEVOX 連携は、なくても M1・M2 の機能が成り立つ(C6)

## 不採用案と理由(逆戻りガード)

- **直線ポインター・蛍光ペンまで M1 に入れる** — 最初に使える状態になるまでが遠くなる。描画処理と JSON の往復を先に固める方が、後の手戻りが少ない
- **ズームを M2 に回す** — ズームなしでは手順書として物足りない(ユーザー判断)
- **M1 を JSON + CLI だけ(UI なし)にする** — In/Out の指定やプレビューを UI なしで行うのは、人には現実的でない

## 前提と再検討の条件

- UI 基盤が Electron である前提([20261029-ui-platform.md](20261029-ui-platform.md))
- M1 で実際に使ってみて、ポインターなしでは手順書として足りない場合は、M2 の一部を前倒しする
