# プロジェクトファイルは秒・ソースのピクセル・画面の割合で書く JSON(2026-10-29 提案)

プロジェクトファイル(要件 T-05)の単位・座標・既定値の扱いなど、形を決める原則についての決定。仕様の本体は [../project-format.md](../project-format.md)。前提は [ステップ単位モデル](20261026-step-based-model.md) と [座標系](20261026-coordinate-system.md)。

## 決定

| 論点 | 決定 |
|---|---|
| 時間の単位 | 秒(小数) |
| 映像側の座標 | ソース映像のピクセル |
| 画面側の座標 | 出力画面に対する割合(0〜1) |
| 文字サイズ | 出力の高さ 1080 基準の px |
| ステップの識別 | 文字列の `id`(必須)。並び順は配列の順 |
| 既定値と上書き | プロジェクト共通の設定を、ステップや要素の同名キーで部分的に上書きする(STY-01/02)。音量も同じ(U-06 の仮決め) |
| 早送り | 種類を表す項目は持たず、`speed` が 1 より大きければ早送り |
| ズーム中の静止 | ズームの `hold: true` は保持と同じものとして扱う |
| ポインター・蛍光ペンの軌跡 | 直線もフリーハンドも、時刻付きの点の列 `path` で持つ。`mode` は編集時のふるまい(スナップ)の区別だけ |
| 知らない項目 | 検証エラーにする |
| 版 | `format` と `version` を必ず持つ |

## 理由

- 秒は人も AI も読みやすい。フレーム番号はフレームレートに依存し、出力設定を変えると値が変わる
- 映像側をソースのピクセルにすると、AI がフレーム画像(AI-03)上で見た位置をそのまま書ける
- 画面側を割合にすると、出力解像度(OUT-02)を変えても配置が保たれる
- `id` があれば「`copy-url` のテロップを変えて」のように並び替えに影響されない指示ができる
- 直線とフリーハンドを同じ形にすると、描画処理と検証が 1 つで済む
- 知らない項目をエラーにすると、AI の打ち間違い(`caption` を `captoin` と書くなど)を見逃さない

## 不採用案と理由(逆戻りガード)

- **時間をミリ秒の整数で持つ** — 誤差は出ないが、人が読みにくい。秒の小数でもミリ秒に丸めれば実用上の差はない
- **時間をフレーム番号で持つ** — fps を変えると値が変わる
- **映像側の座標も割合で持つ** — AI がフレーム画像から割合を計算する手間と誤りが増える
- **早送りを `kind: "fast"` で区別する** — `speed` と二重になり、食い違いが起きうる
- **知らない項目を無視して残す** — 打ち間違いが黙って無視される

## 前提と再検討の条件

- 将来の版で形を変えるときは `version` を上げ、古い版を読み込んで変換する
- 実装で JSON Schema を作るときに、細かい既定値(文字サイズ、ズームの遷移時間など)は調整しうる。U-05(ズームの遷移時間)は未決
