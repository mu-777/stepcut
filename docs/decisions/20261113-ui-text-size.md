# 画面の文字の大きさと、画面全体の表示の大きさ(2026-11-13 決定)

アプリの画面(ヘッダー・設定パネル・ダイアログ)の文字の大きさの基準と、ユーザーが画面全体の大きさを変える方法についての決定。書き出す映像の文字(テロップ)は対象外。

## 決定

- **文字の大きさ**: Windows の Fluent の段に合わせる。本文・ボタン・入力欄は 14px、欄の見出し(`.field-title`・`.field-label` など)は 12px、パネルの見出し(h3)15px・小見出し(h4)13px
- 12px 未満が残るのは、高さを詰めたい所(タイムラインのラベル・目盛り、サムネイル列の補足、バッジ、プレビューの下の帯の名前)だけ
- **欄の見出しにはクラス(`.field-title`)で当てる**。`.field > span` で当てると、入力欄を包む span(フォント・声の選択欄、色の欄)まで小さくなる(この不具合で、フォント・声の欄だけ 11px になっていた)
- **画面全体の表示の大きさ**: Electron の `setZoomFactor` で、Ctrl+プラス / Ctrl+マイナスで 80・90・100・110・125・150・175・200% の段を移り、Ctrl+0 で等倍に戻す。メインの画面に −/＋ のボタンは置かない(ユーザー指定)。アプリの設定の「表示の大きさ(%)」では 50〜300% を 1% 単位の数字で入れられる(ユーザー指定)。段にない値からキーで変えると、その向きのいちばん近い段へ移る。数字は打っている間は当てず、Enter か欄を離れたときに当てる(打ちかけの「1」で 50% に縮まないように)。倍率はアプリの設定(`settings.json` の `uiZoom`)に覚え、読み込み直しても当て直す。メインのウィンドウだけに当て、書き出し用の隠れたウィンドウには当てない
- キーはメインプロセスの `before-input-event` で受ける。「+」の押し方が配列で違うため、=・+・;(日本語配列の + のキー)を受ける。これらはキー操作の割り当てに使えないキー(`RESERVED_KEYS`)に入れる

## 理由

- 以前の本文 13px・見出し 11px は、Fluent の本文 14px・最小 12px より小さかった(ユーザーの指摘)。Windows から始めるアプリなので Windows の基準に合わせる
- 文字だけを段階で変える方式(CSS 変数)は、px の固定値が多く配置が崩れる箇所の確認が広い。画面ごとの倍率は配置ごと拡大縮小するので崩れにくく、実装が小さい
- メニューの accelerator(`CmdOrCtrl+Plus`)は配列によって届かないため、キーの押下を直接見る

## 不採用案と理由(逆戻りガード)

- **文字を小さいまま一覧性を優先する** — 本文 13px・見出し 11px は Windows の最小(12px)を下回る。14px にしても欄の高さの増えは 1〜2px
- **文字の大きさだけを段階で変える(CSS 変数)** — 固定の px が多く、崩れないかの確認が広い
- **OS の表示倍率に任せる(設定なし)** — このアプリだけを大きくできない
- **メインの画面に表示の大きさの −/＋ を置く** — ユーザー指定でキーとアプリの設定の数字だけにする
- **アプリの設定を段の選択欄にする** — ユーザー指定で数字を入れられるようにした(段にない値も使える)
- **Electron の既定の View メニュー(role)の拡大縮小** — 倍率を覚えず、配列によっては + のキーが効かない

## 前提と再検討の条件

- Windows・Mac の実機での見た目(フォントの描画、OS の表示倍率との重なり)は未確認。崩れや大きすぎる所があれば段や基準を見直す
