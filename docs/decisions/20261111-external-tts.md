# VOICEVOX・Azure AI Speech はアプリに組み込み、既定では使えず、ユーザーが同意して有効にする(2026-11-11 決定)

OS 標準以外の読み上げエンジン(VOICEVOX 互換エンジン、Azure AI Speech)への対応と、その使い方の責任をアプリではなくユーザー側に置く仕組みについての決定。[20261026-tts-architecture.md](20261026-tts-architecture.md) の VOICEVOX をプラグインで対応する方針と、クラウドの読み上げを入れない方針を、この記録で置き換える。

## 決定

- 方針(要件 C1 の読み替え): アプリ本体はオフラインで全機能が動く。ユーザーが自分で有効にした接続だけはネットにつながり、費用もユーザーが持つ
- VOICEVOX 互換エンジン(TTS-12)と Azure AI Speech(TTS-13)は、アプリに組み込む(プラグインにはしない)。既定では使えない
- 有効にするのはアプリの設定(パソコンごと)の「読み上げエンジン」。有効にするときに確認を出し、同意した日時を残す(同意の記録がなければ有効にならない)。確認の内容:
  - VOICEVOX: エンジンはユーザーが入れて起動する(同梱しない)。音声は VOICEVOX の利用規約と、使う声(キャラクター)ごとの利用規約に従って使い、内容はユーザーが確かめる。アプリは使い方に責任を負わない
  - Azure: ユーザー自身の契約・鍵・リージョンを使い、料金はユーザーに請求される。読み上げる文は Microsoft に送られる。Microsoft の規約と契約の条件に従い、内容はユーザーが確かめる。アプリは使い方に責任を負わない
- アプリはエンジン・声・鍵を持たない。各サービスの入口として、サービスのトップページだけを開ける(規約そのもののページへは直接つながない)
- Azure の鍵は Electron の safeStorage(OS の資格情報の保管)で暗号化してアプリの設定ファイルに置く。画面(レンダラー)にもプロジェクトファイルにも出さない。暗号化できない環境では保存しない
- 書き出し・試聴の知らせ(TTS-14)は「それぞれの規約(と料金)を確認して従ってください」という内容だけにする。クレジット表記の例など、規約の中身はアプリに書かない
- エンジンはプロジェクト全体で 1 つ(`speech.engine`)。替えたら声の指定を外す。プロジェクトが指定したエンジンを、開いたパソコンで有効にしていなければ OS 標準の声で代わりに読み、そのことを知らせる(有効にしているのにつながらないときは、失敗として知らせる)
- VOICEVOX: `/version` でつながるか確かめ、つながらず「起動していなければ起動する」が入っていれば、指定したプログラムを起動して最大 60 秒待つ。起動は同時の呼び出しで 1 回だけ、起動できなければ(パス違いなど)エラーで知らせる。声はスタイルごと(ID はスタイル ID)。速さは `speedScale` に入れる
- Azure: REST API を直接呼ぶ(SDK は使わない)。声の指定がなければ `ja-JP-NanamiNeural`。速さは SSML の `prosody rate` の % に直す

## 理由

- 使い方の責任(規約・クレジット・料金・送るデータ)は、エンジン・声・鍵を持つユーザーの側にある。既定で使えず、明示の同意で有効にする形にすると、その線がはっきりする
- プラグインの読み込みの仕組み(TTS-02)を先に作るより、組み込みで既定は使えない形の方が、作るのも保守も単純で、上の線は同じように引ける(ユーザーの選択)
- 規約の中身(クレジットの書き方など)をアプリに書くと、相手側が変えたときにアプリの更新が要る。確認を促すだけにする(ユーザーの指定)
- プロジェクトファイルは人・AI と共有するので、鍵を書くと漏れる

## 不採用案と理由(逆戻りガード)

- **別のプラグインとしてユーザーが入れる** — アプリから VOICEVOX・Azure のコードを外せて線はよりはっきりするが、プラグインの読み込み(TTS-02)を先に作る必要があり作業が大きい。今は組み込みで既定は使えない形にした
- **書き出しの知らせにクレジット表記の例を添える(「VOICEVOX:キャラクター名」など)** — 規約が変わるとアプリも直すことになる。確認を促すだけにする
- **VOICEVOX のエンジンを同梱** — キャラクターごとの規約とサイズのため
- **Azure の鍵をプロジェクトファイルや平文の設定に書く** — 共有したときに漏れる
- **使えないエンジンを指定したプロジェクトは書き出しを止める** — ほかの人のプロジェクトを開くと書き出せなくなる。OS 標準で代わりに読み、知らせる
- **Azure Speech SDK を使う** — 依存とサイズが増える。REST API で足りる

## 前提と再検討の条件

- これは仕組みとしての線引きで、法的に十分かの判断ではない。OS 標準の声の商用利用(T-04)と H.264/AAC の特許(T-03)は、どちらも利用者の確認・責任に任せると決めた([20261116-os-voice-commercial.md](20261116-os-voice-commercial.md)、[20261116-codec-patents.md](20261116-codec-patents.md))。配布の範囲を広げる前に見直す
- 実機での接続(VOICEVOX の起動、Azure の鍵と課金)は自動テストで確かめられない(実機確認待ち)
- プラグインの読み込み(TTS-02)を作ったら、VOICEVOX・Azure をプラグインに移すかを見直す

## 呼び出しの制御とキャッシュ

- エンジンごとに同時数の上限を持つ(OS 2・VOICEVOX 1・Azure 3、先着順)。60 秒のタイムアウトは実行が始まってから数える。同じ鍵の要求は 1 回の読み上げを共有する
- キャッシュの鍵に入れる版は、VOICEVOX では接続して分かる版(検索時に起動せず 1 回確かめる)。壊れたキャッシュは作り直す。上限 500 MB を超えたら古いものから消す
