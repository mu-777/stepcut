# 紹介ページは site/ の静的ページを Cloudflare Workers で stepcut.mu-777.dev に置く(2026-11-12 決定、2026-11-14 に構成と見た目を作り直し)

エンドユーザー向けの紹介とダウンロードのページ(LP)の、置き場所・配り方・作り方の決定。アプリ本体のビルドとは独立。

## 決定

- ソースはこのリポジトリの `site/`。静的な HTML と CSS だけ(フレームワークなし。JavaScript は下の言語の振り分けの数行だけ)
- 英語と日本語の 2 枚。英語を `/`(`site/public/index.html`)、日本語を `/ja/`(`site/public/ja/index.html`)に置く。ナビに相手の言語へのリンクを置き、`hreflang`(`x-default` は英語)と `og:locale:alternate` で互いを指す。`/` を開いたとき、ブラウザーの言語(`navigator.languages[0]`)が `ja` なら `/ja/` へ転送する(`<head>` のインラインの JS、`location.replace`)。ナビの言語リンクを押すと選んだ言語を localStorage の `stepcut-lang` に覚え、以後はブラウザーの言語より優先する(`en` なら転送しない、`ja` なら転送する)。`/ja/` から来たとき(保存できない環境で English を押した場合)は転送しない。`/ja/` と 404 では転送しない。2 枚は手で書き、片方を変えたらもう片方も直す(`.claude/rules/lp-media.md`)。404 のページは両方の言語を並べる
- 動画・画像・OGP 画像も言語ごとに作る(英語は `media/en/` と `og.png`、日本語は `media/` と `og-ja.png`)。英語の書体は IBM Plex Sans と Sora
- 配信は Cloudflare Workers の静的アセット。Worker 名 `stepcut-lp`、Custom Domain `stepcut.mu-777.dev`(`site/wrangler.toml`)
- デプロイは Cloudflare の Workers Builds(Git 連携)。main への push で、`site/` に変更があれば `npx wrangler deploy` が走る。ルートディレクトリ・watch paths は Cloudflare のダッシュボード側の設定
- 見た目はアプリの配色(`--bg` `#1e1f22`、`--panel`、`--line`、`--accent` `#4f8cff`)に合わせ、ブラウザの設定によらず暗い地で固定する。雰囲気は同じ作者の [DayGlassBar のページ](https://mu-777.github.io/dayglassbar/)にそろえる(細い線のナビ、丸いバッジ、光る青のボタン)
- 名前を目立たせる: ヒーローの見出しの上にロゴを置く(PC は高さ 98px で、ロゴの文字の高さを h1 の和文の字面にそろえる。h1 は最大 40px。820px 以下は高さ 72px)。ナビは画面上端に固定する(`position: sticky`、半透明の地)。ページの上端でナビとヒーローにロゴが 2 つ並ぶのは可とする
- 構成: ヒーロー(左に文、右に動画)→ 機能を絞っていること(編集画面、「ないもの / その代わり」の対、手間が減る点 2 つ)→ 使い方(動画と 4 つの作業)→ 付けられるもの(9 つを小さな動画と名前、ひとことで並べる)→ 使いみち(操作の手順・製品のデモ・資料の解説の 3 例。例ごとに、できた動画と編集画面を並べる)→ 事実の帯(オフライン・無料・AI での編集 β)→ FAQ → ダウンロード
- 何のツールかは、用途ではなく、することで言う: 「録画を、説明付きの動画に」。説明の手段はテロップ・読み上げ・ズーム・ポインター・図形。用途(操作の手順、製品のデモ、資料の解説)は例として添える
- 「何を付けられるか」は、付けられるもの 9 つ(テロップ・読み上げ・ズーム・ポインター・蛍光ペン・四角・矢印・テキスト・画像)を、同じ場面に 1 つずつ付けた小さな動画と、名前・ひとことで見せる。読み上げは、テロップと同じ動画に「音が出ている」印を重ねる(動画は音声なしで載せるため)。そのうえで、使いみちの例の中で使われている様子を見せる。例ごとに使う機能を分け、3 例で一通りになるようにする(手順: 切り分け・ポインター・四角・早送り / デモ: ズーム・止めて見せる・テキスト・画像・フェード / 資料: 画像のステップ・蛍光ペン・矢印)。早送り・保持・フェードは使いみちの例で見せ、読みの辞書・SRT・背景はページに載せない
- 訴え方: 汎用の動画編集ソフトではなく、説明を付けることに絞っていること。「簡単」とは書かず、絞った結果を事実で述べる
- 文面: 普通の文で事実を述べる。対句・言い切り・「〜だけ」「不要」の強調は使わない。利点は肯定形で書く(「少ない」「固定」ではなく「シンプル」「見渡せる」)。項目は、ほかのツールでは当たり前でないものだけを載せる
- 動画と編集画面の画像は StepCut 自身で作る(`scripts/make-lp-media.cjs`。手順は [docs/lp-media.md](../lp-media.md))。自動で再生する動画は音声なし。「使い方」の動画だけは操作の付いた動画にして読み上げ(Azure AI Speech)を入れ、StepCut が書き出した字幕も付ける
- ダウンロードのボタンは `releases/latest/download/StepCut-Setup.exe` で最新のリリースを直接指す。ダウンロードの節には portable 版(`StepCut-Portable.exe`)のボタンも置く([20261116-release-flow.md](20261116-release-flow.md))
- フォントは Google Fonts の IBM Plex Sans JP(本文・見出しの和文)と Sora(見出しの欧文・数字。ロゴと同じ書体)。英語のページは IBM Plex Sans JP の代わりに IBM Plex Sans を読む

## 理由

- ランニングコストゼロ(C1)。Workers の静的アセットと Workers Builds は無料の範囲で足りる。ドメインは既に Cloudflare にある
- サブドメインにすると、同じドメインのポートフォリオ(Worker `my-portfolio`)と経路が重ならず、設定は Custom Domain の 1 行で済む(DNS と証明書は Cloudflare が作る)
- Workers Builds は GitHub に API トークンを置かずに済む
- 1 ページで、動きは動画だけなので、ビルドの要る仕組みは持たない。アプリの依存(package.json)にも足さない(wrangler は `site/package.json` だけ)
- 構成は、動画編集ツールのページ(Screen Studio・Cap・Tella・Descript・Guidde)と DayGlassBar を要素に分け、StepCut に条件がそろっているものだけを採った。機能ごとに「得られる結果の見出し + 証拠の動画」(Screen Studio)、小さな機能の格子(同)、制作の流れを 1 本で見せる(Descript)、最後のダウンロードが締めの呼びかけを兼ねる(DayGlassBar)
- 動画を StepCut で作ると、ページそのものがアプリで作れるものの見本になる。スクリプトにしてあるので、画面を変えたら作り直せる
- 英語を `/` にするのは、アプリの UI が英語を主にしている(NF-07)ため。言語で自動で振り分けるのは、日本語の利用者が英語のページから入らずに済むようにするため(ユーザーの要望)。Google は言語を推測した自動リダイレクトを避けるよう勧めている([Managing multi-regional and multilingual sites](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites))。理由は、利用者と検索エンジンがほかの言語版を見られなくなること。これには次のように対処した: Googlebot は `Accept-Language` なしで米国から来る([Locale-adaptive pages](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages))ので `/`(英語、`x-default`)がそのまま返り、`/ja/` は `hreflang` とリンクで見つかる。転送は `/` だけで、言語リンクで選び直した言語を覚えるので、利用者はどちらの版も開ける
- 振り分けをページの JS でするのは、静的ファイルのまま(Worker のスクリプトなし)で済むため
- 英語のページに日本語の動画を載せると、テロップと画面が読めない。動画はスクリプトで作るので、言語ごとに作っても手間は実行 1 回分

## 不採用案と理由(逆戻りガード)

- **`mu-777.dev/stepcut`(パスで分ける)** — Worker のルートと `assets.base_path` で実現でき、ルートは同じホストの Custom Domain より優先されるので共存もできる。ただしポートフォリオ側の割り当て方に依存し、設定が増える。ユーザーがサブドメインを選んだ
- **GitHub Actions + wrangler deploy** — `paths:` で条件を書けるが、Cloudflare の API トークンを GitHub Secrets に置く必要がある
- **GitHub Pages** — 独自ドメインを Cloudflare から向ける設定が別に要る。ほかのページと同じ Cloudflare にそろえた
- **OS のテーマに合わせた明るい配色** — アプリが暗い地だけなので、スクリーンショットと地をそろえる
- **OS 標準のフォントだけ** — 見出しの印象が OS で変わる。ポートフォリオも Google Fonts を使っている
- **ほかのページの構成をそのまま使う(DayGlassBar 型・Screen Studio 型・Cap / Tella 型の 3 案)** — ユーザーが、要素単位で組み合わせる方を選んだ
- **中央の大見出し + 画面幅いっぱいのデモ** — ユーザーが左右の配置を選んだ
- **見出しの 2 行目(薄い色の副題)** — ユーザーが不要と判断
- **「手順が伝わる動画」「手順を見せる動画に絞った」という言い方** — 手順のためだけのツールではない。用途で言うと、デモや紹介に使いたい人が自分向けと思わない
- **「言葉で説明を付ける」** — ズームやポインターも説明の手段で、言葉だけではない
- **機能ごとの節(テロップ・ズーム・指す の 3 節に動画 1 本ずつ)** — 機能だけを見せるより、使われている様子と一緒の方が、自分の用途に合うかが伝わる。機能は一覧にまとめ、動画は使いみちの例に寄せた
- **例に「不具合の報告」** — ユーザーが外した。ほかの例で見せられない機能(画像のステップ・蛍光ペン)を見せられる「資料の解説」にした
- **機能を文字で一覧にする(タイムラインの段ごとに 17 項目)** — 文字の一覧は読まれない。知りたいのは網羅ではなく「何を付けられるか」なので、絵で答える
- **全部の種類を 1 コマに載せて引き出し線を付ける** — 8 種類を 1 枚に載せると込み合い、どれがどれか分かりにくい
- **「テロップを書くと、声になる」を別の図(文と波形の一覧)で説明する** — 読み上げの枠の中で言えば足りる。読み上げだけ図だと、ほかの 8 つ(動画)と並べたときに浮く
- **編集前 → 編集後の比較** — テロップや図形を付けるかは使う人が決めること。「こう変わる」とは言い切れない
- **「社内の手順書に使える理由」という節** — 社内の手順書のために作っているわけではない。オフライン・無料は、用途を付けずに事実の帯に置く
- **「何でもはできません。そのぶん、迷いません。」のような言い切りの見出し** — 仰々しい。参考にした文面は [Orito](https://www.orito.ai/)
- **項目を増やす(取り消し・やり直し、並べ替え、解像度、「書き出してからの見直しが不要」など)** — どの動画編集ツールにもある。載せない
- **名前を h1 に入れる(「StepCut で、録画を…」)/ バッジに名前を入れる / ダウンロードの節だけ強める** — 見出しが長くなる、または効果が弱い。ユーザーがヒーローのロゴ + ナビの固定を選んだ
- **ヒーローが見えている間はナビのロゴを隠す** — JS と動きが増える。ユーザーが 2 つ並んでよいと判断
- **ヒーローの機能タブ、利用者の声・スター数、作品集、料金表** — モードも実績も作例もまだなく、無料でアカウントもない
- **CSS で描いた仮の絵のまま載せる** — StepCut で作った実物の方が、アプリの見本になる
- **日本語を `/` のままにし、英語を `/en/` に置く** — 今のリンクは変わらないが、UI が英語を主にしている(NF-07)ことと合わない。ユーザーが英語を `/` にする方を選んだ
- **Worker で `Accept-Language` を見て振り分ける** — 英語のページが一瞬見えることはないが、Worker のスクリプトとデプロイの設定が増え、キャッシュを言語ごとに分ける配慮が要る
- **自動では振り分けず、日本語のブラウザーに「日本語版があります」の帯を出す** — Google の勧めにいちばん沿うが、1 クリック要る。ユーザーが自動の転送を選んだ
- **ブラウザーの言語の 2 番目以降も見る** — `en-US, ja` の人は英語を先に置いている。先頭だけで判断する
- **振り分けない** — 日本語の利用者が英語のページから入る
- **テンプレートから 2 言語をビルドで作る** — ずれは防げるが、ビルドの仕組みを持たない決定に反する
- **英語のページに日本語の動画をそのまま載せる** — 手間はないが、テロップと画面が読めない

## 前提と再検討の条件

- 動画と画像は Linux のコンテナで作ったもの(文字が Windows のフォントでない、読み上げが無音)。Windows で作り直したら差し替える
- AI での編集は β。正式にしたら、帯の「β」を外し、扱いを大きくするか見直す
- 「ないもの」(自由なトラック、凝ったトランジション、録画)は要件 3.2 と UI-03 による。機能を足したらページも直す
- 最初のリリースを出すまで、ダウンロードのリンクは 404 になる
- コード署名をしていない(NF-08)ので、SmartScreen の警告の手順をページに書いている。署名をしたら消す
- 「使い方」の動画のシークは、配信側が範囲指定の読み込み(Range)に応えることが前提。手元の `wrangler dev` は応えない。本番で応えなければ、Worker で範囲指定を処理するか、動画の置き場所を変える
- 動画が自動で再生される。動きを減らす設定(prefers-reduced-motion)の人にも再生される(JavaScript を使わないため止められない)。問題になったら、数行のスクリプトを足すか、操作の付いた動画にする
