# 読み上げは OS 標準を内蔵し、プラグインで拡張する(2026-10-26 決定)

読み上げエンジンの構成、読みの辞書の置き場所、VOICEVOX 対応の方式についての決定。

## 決定

- OS 標準の音声合成を本体に内蔵し既定とする。内蔵エンジンもプラグインと同じインターフェース(入力: 文章・声・パラメータ、出力: wav と長さ)で実装する
- プラグインは別プロセス(標準入出力またはローカル HTTP)で動かし、開発言語を問わない
- 読みの辞書は本体の機能とし、エンジンに渡す前に文字列を置き換える
- VOICEVOX 互換エンジンはローカルの HTTP API に接続するプラグインで対応する。exe パス指定と自動起動に対応し、エンジンは同梱しない

## 理由

- プラグインなしで全機能が動く必要がある(C6)
- 辞書を本体に置けば、エンジンを問わず同じように効く
- VOICEVOX はキャラクターごとに利用規約があり、サイズも大きい。YMM4 が同じ方式で連携している前例がある

## 不採用案と理由(逆戻りガード)

- **クラウド TTS(Clipchamp の Azure AI Speech 等)** — ローカル完結(C1)とランニングコストゼロに反する
- **VOICEVOX エンジンを同梱** — キャラクターごとの規約とサイズのため
- **辞書を各エンジン任せにする** — エンジンを替えると読みが変わる。エンジン側の辞書(アクセント等)は各エンジンの機能として使えればよい

## 前提と再検討の条件

OS 標準音声の出力を商用利用してよいかは未確認(要件 T-04)。不可と分かった場合は既定エンジンと案内(TTS-11)を見直す。
