# H.264/AAC の特許は利用者の責任と明記して配布する(2026-11-16 決定)

H.264/AAC の特許(要件 T-03)への対応と、ハードウェアエンコーダーがない環境でのソフトウェア代替(要件 T-02)の扱い。調べた事実は [../codec-patents.md](../codec-patents.md)。

## 決定

- 特許プール(Via LA)とは契約しない。README と THIRD_PARTY_NOTICES.md に「H.264/AAC の特許への対応は利用者の責任」と書く
- 書き出しの経路は今のまま。映像はハードウェアエンコーダーを優先し、なければ Electron 内蔵の OpenH264 で書き出して警告を出す。音声は OS の AAC、なければ Opus
- ソースのライセンスは Apache-2.0 のまま(特許と著作権ライセンスは別の問題)

## 理由

- OS のエンコーダーに任せても回避できない。Electron は H.264/AAC 入りの FFmpeg(デコード)と OpenH264 を同梱しており、配布すること自体が実施(譲渡)に当たりうる。Windows の H.264 の許諾も個人的・非商用に限る
- 同種のオープンソースのツール(OpenScreen・Recordly)と Electron のアプリ全般は、特許に触れずに配布している。StepCut が配布する実装はそれらより少ない
- 利用者の主な用途(社内の手順書、無料の公開)は、コンテンツ側の特許料がかからない範囲にある
- 個人運営のオープンソースで、ランニングコストゼロ(C1)。プール契約の報告の義務と AAC の料金(1 台目から)は負えない

## 不採用案と理由(逆戻りガード)

- **ソフトウェア代替(OpenH264)を止める** — Electron の FFmpeg のデコーダーが残るので効果は小さく、古い PC で書き出せなくなる
- **H.264/AAC なしで Electron をビルドする** — H.264 の録画を読めなくなる。Electron を自前でビルドし続ける手間が大きい
- **Via LA と契約する** — H.264 は年 10 万台まで無料だが報告の義務があり、AAC は 1 台目から有料。体制に合わない
- **Cisco の OpenH264 バイナリを使う** — 実行時に別途ダウンロードさせる条件で、同梱できない。WebCodecs からは使えずネイティブのアドオンが要り、Electron 内の実装も残る
- **WebM(AV1/VP9 + Opus)で書き出す** — PowerPoint や社内の動画の基盤で再生できない恐れがあり、mp4 の要件と合わない。録画の読み込み(H.264)は残る
- **GPL 系にライセンスを変える** — 特許の助けにならない。GPL-3.0 §12 でかえって制約が増える

## 前提と再検討の条件

- 有償で売る、企業として配布するなど、配布の形が変わったら見直す(プール契約か専門家への相談)
- 特許権者や Via LA から連絡があったら見直す
- 米国の H.264 の特許は 2030 年ごろ、AAC は 2028〜2031 年ごろに切れる。切れたらこの記録は不要になる
