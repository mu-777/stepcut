# レンダラーの IPC をパスの許可リストとナビゲーション禁止で縛る(2026-11-11 決定)

メインプロセスがレンダラーに公開するファイル操作・設定の IPC に、許可リスト(allowlist)とナビゲーション禁止をかける。`sandbox: false` は当面維持する。

## 決定

- すべてのウィンドウで、新しいウィンドウ(`setWindowOpenHandler`)・`will-attach-webview`・別オリジンへの `will-navigate` を禁じる(開発時の dev サーバーのオリジンだけ許す)
- ファイルのパスは `src/main/access.ts` の許可リストで縛る。許可されないパスは `許可されていないパスです / Path not allowed` で拒否する
  - 読んでよい: 開くダイアログ(素材・画像)で選んだパス、プリロードがドロップされたファイルから得たパス、既知のプロジェクトを基準に解決した素材のパス、書いてよいパス
  - 既知のプロジェクト: 起動引数、開くダイアログで選んだもの、保存したもの、名前を変えたもの、CLI のジョブのもの。`project:read` / `project:save`(保存先を指定するとき)/ `project:rename` はこれだけ。名前の変更はフォルダーを抜ける名前・使えない文字を断る
  - 書いてよい: 書き出しの保存ダイアログで選んだ mp4 とその `.srt`、CLI のジョブの出力先。`output:open` と `file:write-text` はこれだけ。`file:reveal` は書いてよいパスか既知のプロジェクト
  - VOICEVOX の実行ファイルは、選択ダイアログで選んだものか今の設定と同じものだけ設定できる
- 書き出しは出力先の隣の一時ファイル(`.part`)に書き、成功したときだけ置き換える

## 理由

レンダラーは外部の画像・プロジェクトファイル(AI が書く JSON を含む)を扱う。描画や依存の脆弱性でレンダラーが乗っ取られても、任意のファイルの読み書きや任意の実行ファイルの起動につながらないようにしたい。`sandbox: false` のままでもプリロードは信頼でき、ナビゲーションを禁じれば外部のページが `window.api` を得る経路もなくなる。許可の元はメインプロセスのダイアログとプリロードだけにして、レンダラーの引数は信用しない。

## 不採用案と理由(逆戻りガード)

- **今すぐ `sandbox: true`** — プリロードで `webUtils` 以外の Node 機能を使っていないので将来は可能だが、E2E・CLI(非表示ウィンドウ)・mediabunny の挙動への影響を確かめきれていない。許可リストで IPC の権限を絞るほうが先で、効果も大きい
- **ナビゲーション禁止だけ** — 乗っ取られたレンダラーが IPC を直接呼ぶ経路は残る(任意パスの読み書き)

## 前提と再検討の条件

- 許可リストはプロセス内のメモリだけ(再起動で消える)。開き直すには、ダイアログか起動引数を通す
- `sandbox: true` に移れるか確かめられたら見直す(プリロードが `webUtils` と `ipcRenderer` だけを使う間は移れる見込み)
