# StepCut のプロジェクトを編集する

StepCut は、画面録画(と画像)をステップに切り分け、テロップ・読み上げ・ズーム・ポインター・図形を付けて mp4 の手順書動画を作るデスクトップアプリ。編集内容は JSON のプロジェクトファイル(`*.stepcut.json`)にすべて入っていて、アプリは外部の変更を検知して読み直す。だから **JSON を直接書けば編集できる**。CLI は、JSON だけでは分からないこと(画、計算後の時刻)を知るためと、検証・書き出しのために使う。

- 書き方の全仕様: [project-format.md](project-format.md)(必ず先に、触る要素の節を読む)
- 機械向けのスキーマ: [project.schema.json](project.schema.json)

## 1. CLI を呼ぶ

CLI はアプリの実行ファイルそのもの。同梱のスクリプトが場所を探して実行し、結果の JSON を標準出力に出す(`--json` と `--result` は付けなくてよい)。終了コードは成功 0、失敗 1、引数の誤り 2、CLI が見つからない 3。

```bash
bash ${CLAUDE_SKILL_DIR}/scripts/run-cli.sh <コマンド> ${CLAUDE_PLUGIN_DATA} <project.stepcut.json> [オプション...]
```

- `validate` と `frame` は読むだけ(`frame` は PNG を書く)なので、上の形のまま書けば確認なしで実行できる。パイプや `&&` でほかのコマンドをつなぐと確認が出る。パスに空白があって引用符が要るときも確認が出ることがある
- `inspect`(読み上げを実際に作る)と `export` は、ユーザーが有効にした外部の読み上げエンジンに文を送ることがあるので、確認が出る
- 終了コード 3 なら CLI が見つかっていない。ユーザーに StepCut の実行ファイル(またはインストールしたフォルダ)の場所を聞く。インストーラの既定は Windows なら `%LOCALAPPDATA%\Programs\StepCut\StepCut.exe`(すべてのユーザーに入れたなら `C:\Program Files\StepCut\`)、ポータブル版はユーザーが置いた場所。聞いたら覚えさせる(次から聞かずに済む):

  ```bash
  bash ${CLAUDE_SKILL_DIR}/scripts/find-cli.sh ${CLAUDE_PLUGIN_DATA} --save "<聞いたパス>"
  ```

- `frame`・`inspect` が引数の誤り(2)で「コマンドが違います」になる、または画面が開いて終わらないなら、アプリが古い。ユーザーに更新を頼む(validate・export だけは使える)

## 2. コマンド

以下の表は `run-cli.sh <コマンド> ${CLAUDE_PLUGIN_DATA}` に続く部分だけを書く。

| コマンド | 使いどころ | 結果 |
|---|---|---|
| `inspect <p>` | 編集の前後で、ステップの開始時刻・長さ・読み上げの実際の長さ・自動の保持・テロップ・ズーム・オブジェクトの出ている間を知る | `steps[]`(`start`/`end` は全体の時刻、ほかはステップ内の時刻) |
| `frame <p> --step <番号\|id> --time <秒> --source --out a.png` | 座標を決める。素材(録画・画像)のフレームをそのまま出す。**この画像のピクセル = 映像側の座標**なので、見た位置をそのまま書ける | `imageSize`、`sourceTime` |
| `frame <p> --step <番号\|id> --time <秒> --out b.png` | 仕上がりを確かめる(書き出しと同じ見た目) | `geometry`: 画像の点 → 映像側の座標は `x = view.x + (px − box.x) / scale` |
| `frame <p> --at <秒>` | 全体の時刻で指定する | 同上 |
| `validate <p>` | 書いたら毎回。エラーの `path` が直す場所。素材・背景・図形・ポインターの画像ファイルがなくてもエラーになる | `errors[]`、`warnings[]`(各 `{ path, code, message }`。`message` は英語、`code` は種類) |
| `export <p> --out v.mp4` | 動画にする(時間がかかる。ユーザーが望んだときだけ) | `outPath`、`duration` |

`--step` は 1 始まりの番号かステップの `id`。`--time` はステップ内の出力時刻(秒)。出した PNG は Read で見る。

- `--time` がステップの長さを超えると、末尾のフレームを出して `warnings` で知らせる(成功のまま)
- 結果の `warnings` は毎回読む

## 3. 進め方

1. プロジェクトファイルを読み、`inspect` で時間の全体像をつかむ
2. 付ける要素の時刻を決める。読み上げに合わせるなら `inspect` の `speech[].start` / `end` を使う(読み上げの長さは JSON には書かれていない)
3. 座標が要る要素(ズーム・ポインター・図形)は、その時刻の `frame --source` を見て、指したい物のピクセル座標を読む
4. JSON を書く。書いたら `validate`
5. `frame`(`--source` なし)で仕上がりを見て、ずれていれば直す。読み上げを変えたら `inspect` で時刻を取り直す
6. ユーザーにどこをどう変えたか伝える。アプリを開いていれば自動で読み直される(アプリ側に保存していない変更があると、どちらを使うかユーザーに聞く)

### 録画から新しく作るとき

プロジェクトファイルがまだないときは、先に最小のプロジェクトを書く。CLI はプロジェクトを通してしか録画を読めない。

1. 録画と同じフォルダーに、録画全体を 1 ステップにした仮のプロジェクトを書く(`out` は長めの仮の値でよい)

   ```json
   {
     "format": "stepcut.project",
     "version": 1,
     "sources": [{ "id": "rec1", "path": "録画.mp4" }],
     "steps": [{ "id": "all", "source": "rec1", "segments": [{ "in": 0, "out": 36000 }] }]
   }
   ```

2. `frame --step 1 --time 0 --source` の結果の `sourceSize` で録画の大きさを知る。録画の長さは、`--time` を大きくしていって画が変わらなくなる所で見当を付ける(`out` が録画より長くても、最後のフレームが出るだけでエラーにはならない)。ユーザーが長さを知っていれば聞く方が早い
3. 一定の間隔(5〜10 秒)で `frame --source` を見て、操作の区切りを探す。区切りの前後は間隔を詰めて、`in` / `out` を決める
4. 仮のステップを、決めた `in` / `out` の区間(`segments: [{ "in": …, "out": … }]`)のステップに置き換え、テロップ・読み上げを書く。ここからは上の 1〜6 と同じ

## 4. 間違えやすいところ

- **時刻は 2 種類**: ステップの区間 `segments[].in` / `out` だけが素材(録画)の時刻。テロップ・読み上げ・ズーム・保持・ポインター・図形の時刻はすべて**ステップ内の出力時刻**(ステップの頭が 0、保持・早送りの後)
- **区間**: `segments` は区間が 1 つでも配列。2 つ以上なら並び順に続けて再生する(間を飛ばす・戻るのも可。同じ録画で速度が同じステップをまとめたもの)
- **ステップの長さ**: 各区間の (`out` − `in`) の合計 ÷ `speed` + 保持。読み上げ(または `end` を書いたポインター・図形)の方が長ければ最後のフレームで自動的に待つ(自動の保持)。最初の読み上げは `start` を書かなければ全体の `speech.startOffset`(既定 1 秒)から読む
- **座標は 2 種類**: ズーム・ポインター・図形は映像側(素材のピクセル、左上が原点)。テロップの位置は画面側(出力に対する割合 0〜1)。画面に固定した図形(`anchor: "screen"`)は出力の高さ 1080 を基準にした px
- **画像の素材**: `sources` の `path` が png・jpg・webp なら画像。どの時刻も同じ 1 枚で、区間は 1 つ・長さだけを表す(`segments: [{ "in": 0, "out": 3 }]` なら 3 秒)
- **継承**: 見た目・読み上げの声・録画の枠は「既定 ← 全体(`styles` / `speech` / `layout`)← ステップの上書き」。人が書いていない既定値を書き足さない。全体をそろえたいなら全体に書き、例外のステップだけに上書きを書く
- **書かないこと**: `format` / `version` は変えない。`sources` のパスはプロジェクトファイルからの相対パスのまま。ステップの `id` は重複させない(画面には出ない名前。差分やユーザーとの会話で使う)
- 1 つのステップに複数の読み上げを置ける(配列)。1 つ目の `text` を省くとテロップの文を読む
